## File and deployment integration

`StaffPayslip` and `StaffDocument` are new read-side integration contracts because the repository has no authoritative payroll/document producer. Populate only through separately trusted provisioning, with reviewed owner/Branch identity. A payslip requires approved status and approvedAt; a document requires visibleToOwner. `hasFile` must reflect actual content and MIME. Allowed file types are PDF/PNG/JPEG, at most 10 MB for delivery. Never set hasFile for a nonexistent generated document. No demo/production data was inserted.

Android decodes authorized file bytes into private app cache and grants a viewer a single read URI through a non-exported FileProvider. Cache files older than one hour are purged on a subsequent file open. The app requests no public storage permission. The external viewer handles user-directed save/export. Missing viewer or unsupported device returns an error, not a fake download confirmation. Existing shared API authentication is used; no public URL or signed bearer token is given to another app.

The server ensures all five domain indexes before accepting traffic. Existing replica-set/sharded topology prerequisites still apply. The shared Branch fence serializes staff conflicts conservatively with other Branch mutations; it favors correctness over parallel write throughput. Leave approval records time off but does not account for holidays/working-day allowances or allocate cover.
